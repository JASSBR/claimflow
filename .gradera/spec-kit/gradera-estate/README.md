# Gradera estate preset for Spec Kit

Generated by the Gradera AI-DLC Kit for `claimflow` (package `beb846ce-e849-4d0f-9a6d-bffd7d4b15be`, kit layout `spec_kit_copilot`). It grounds the Spec Kit workflow in what the Gradera Context Engine holds about this repository: approved rules as constraints, impact before a plan, the kit's skills in every task. Every fact is read from the `gradera` MCP server when a command runs; this preset carries none of its own.

## Install

Needs Spec Kit `>=1.2.0,<2.0.0` (`specify version`) in this repository with the `copilot` integration, and the `gradera` MCP server configured for the agent.

```sh
specify init --here --integration copilot   # only when .specify/ is absent
specify preset add --dev .gradera/spec-kit/gradera-estate
specify preset list
```

## Update and remove

When a newer kit is promoted and its files are written here:

```sh
specify preset update gradera-estate --dev .gradera/spec-kit/gradera-estate
```

`specify preset remove gradera-estate` puts the core commands and templates back as Spec Kit ships them.

## What it never touches

`.specify/memory/constitution.md` and `specs/` are the team's, and the rest of `.specify/` is Spec Kit's. The preset composes through Spec Kit's own resolution, so `specify integration upgrade` and `specify preset remove` keep working as Spec Kit documents them. The constitution command proposes principles from approved rules and leaves the decision to the team.

The repository's always-on instructions are not part of the preset: `.github/copilot-instructions.md` and `AGENTS.md` are the kit's own files, and stay where the agent reads them at the start of every session.
